## [Unreleased]

### Added
- **Models per phase** ([the loop](docs/concepts/the-loop.md#models-per-phase)): Opus to decide and to
  review, Sonnet to build, one session per phase with `SPEC.md` and `tasks/` carrying the context.
  - The personas run on a model of their own, written into `agents/` by `scripts/aliases.mjs`
    (`PERSONA_RUNTIME`): `kaizen:code-reviewer` and `kaizen:security-auditor` on Opus, effort `high`;
    `kaizen:test-engineer` and `kaizen:web-performance-auditor` on Sonnet. A contract test holds every
    persona to a model, and no command to one.
  - New `models` configuration key, off by default (`models.enabled: false`) until measured: with it,
    `kaizen status` and `/kaizen:setup` name, with the next command, the session to open for it
    (`claude --model sonnet --effort medium` for `/kaizen:build`) — advice, Kaizen never changes the model.
  - The quality gate escalates: from block `models.escalate_after` (2) on, its report asks for a subagent
    on Opus to find the root cause (or `/advisor opus`); the first escalation is logged as `escalated`
    in `friction.jsonl` and counted by metrics (`friction.quality.escalated`).
- **`evals/run.mjs --model <id> --effort <level>`**, passed to `claude -p`, for A/B runs on a pinned model.
- **A warning when `/kaizen:build` starts on another model than `models.build`** (with `models.enabled`):
  new `scripts/model-hooks.mjs`, registered on `SessionStart` and `PostModelSwitch` (`--record`: the
  session's model in `.kaizen/state/session-model.json`) and on `UserPromptExpansion` for `/kaizen:build`
  (`--command`: a `systemMessage`, never a block; the last answer's model in the transcript when none was
  recorded; silent when unknown). Eleven hook registrations.
- **`/kaizen:build-fork`**, off by default (`models.build_fork: false`): agent-skills' `/build`, one task,
  run with `context: fork` on the new `kaizen:fork-builder` agent (Sonnet, effort `medium`), both generated
  by `scripts/aliases.mjs`. Refused while off, and for `auto` (a fork cannot wait for an approval);
  `status` offers it next to the fresh session.
- **[Features](docs/features.md)**: every feature Kaizen adds, when it runs and how to turn it off; and
  **where the workflow files live**, at the top of [State and files](docs/reference/state-and-files.md).

### Changed
- **Models and efforts per phase revised** (`DEFAULT_CONFIG.models`, still off by default): effort `high`
  only where a miss costs the most later. Opus `medium` for ideate, spec and the other design commands,
  Opus `high` for plan; Sonnet `medium` for build, test, code-simplify, webperf and now debug (it moves to
  the build phase; the quality gate escalates it); Sonnet `low` for watch, learn and metrics; Opus
  `medium` for review and ship, Opus `high` for security. The escalation names its model and effort:
  new `models.escalate_to` (`opus`) and `models.escalate_effort` (`high`), passed as the Agent tool's
  `model` and `effort`. Personas: `kaizen:code-reviewer` Opus `medium` (was `high`),
  `kaizen:security-auditor` Opus `high`, `kaizen:test-engineer` Sonnet `medium`,
  `kaizen:web-performance-auditor` Sonnet `low`.
- **`kaizen cost` and metrics price each token type at its own price**: input, cache write (5-minute and
  1-hour), cache read and output, per model family (`fable`, `opus`, `sonnet`, `haiku`), at Anthropic's
  API list prices in $ (`scripts/ledger.mjs` `PRICES`, overridable with the new `cost.prices` key). Items
  gain `unit`, `cost_by_model` and `cost_by_type`. Before, every token weighed the same, so a cache read
  (1/100 of an output token on Opus 5.5) counted as much as an output token, with Sonnet at 3/5 of Opus
  instead of 1/2. Costs recorded before are re-priced on read: the ledger keeps the raw counts.

### Deprecated
- `review.cost_weights`: still honoured while `cost.prices` is empty, in the former relative units, and
  `kaizen cost` says it is deprecated.

## [1.1.0] - 2026-11-11

### Changed
- **agent-skills is embedded in Kaizen: one plugin to install.** The copy moves from
  `plugins/agent-skills/` to `plugins/kaizen/agent-skills/` (still unmodified, still updated by pull
  request). Its skills load as `kaizen:<skill>` (`plugin.json` `skills`), its personas as
  `kaizen:code-reviewer`, `kaizen:security-auditor`, `kaizen:test-engineer`,
  `kaizen:web-performance-auditor` (`agents/`, generated by `scripts/aliases.mjs` like the commands).
  `agent-skills@dojo` leaves the marketplace; `install settings` declares `kaizen@dojo` only.
- **`kaizen doctor`'s `agent_skills` check** shows the embedded version, and warns when
  `agent-skills@dojo` is still enabled (its skills would load twice).

## [1.0.0] - 2026-11-11

Kaizen is the engine around Addy Osmani's [agent-skills](https://github.com/addyosmani/agent-skills),
shipped next to it in the dojo marketplace: agent-skills does the work (spec, plan, build, test, review,
ship), Kaizen adds what it does not do — gates the agent cannot talk its way past, memory between
cycles, PR follow-up and measurement.

### Added
- **agent-skills' commands under `/kaizen:`**: `spec`, `plan`, `build`, `test`, `review`, `ship`,
  `constraints`, `code-simplify`, `webperf` — exact copies of its commands, generated by
  `scripts/aliases.mjs` and regenerated when agent-skills is synced.
- **Entry points onto agent-skills' skills that have no command**, generated by the same script:
  `/kaizen:ideate` (`interview-me`, `idea-refine`), `/kaizen:debug` (`debugging-and-error-recovery`),
  `/kaizen:adr` (`documentation-and-adrs`), `/kaizen:security` (`security-and-hardening`),
  `/kaizen:doubt` (`doubt-driven-development`), `/kaizen:migrate` (`deprecation-and-migration`).
- **Four skills** in agent-skills' anatomy: `/kaizen:setup` (configuration, both plugins declared,
  doctor, next command), `/kaizen:learn` (capture, harvest, prune), `/kaizen:metrics` (DORA approximated,
  learnings reuse, friction, cost per work item), `/kaizen:watch` (a PR followed to "looks ready").
- **Quality gate**: as soon as a session edits code, the turn cannot end while the checks are red
  (`gate.max_blocks` at most).
- **Review before push**: agent-skills' review records itself (its review skill or its `code-reviewer`
  persona, verdict read from what it wrote); an unreviewed push is stopped once, Claude asks, and only
  the user lets it out in Claude Code's own prompt.
- **No secret committed**: about thirty key and token formats, `--no-verify` refused, in every repository.
- **Learnings read back**: one lesson per file in `docs/learnings/`, added to Claude's context when
  `SPEC.md` or `tasks/` are written, or when a file a learning names in `files:` is edited.
- **Cost per work item**: every turn's tokens charged to the branch's Jira key (else the branch), for
  `kaizen cost` and `/kaizen:metrics`.
- **`kaizen` CLI** (Node ≥ 18, no dependency): `status`, `doctor`, `verify`, `gate`, `review`, `secrets`,
  `learnings`, `metrics`, `cost`, `pr`, `install settings`, `init`, `config`, `detect`, `root`.
- **Documentation**: getting started, one guide per skill, concepts, reference, troubleshooting,
  positioning.
