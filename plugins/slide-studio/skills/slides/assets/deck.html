Why it matters

Size is the first predictor of review quality.

Chapter divider: pause, breathe, one sentence.

Big pull requests don’t get reviewed. They get approved.

Let it land. Say nothing for two seconds.

The problem

Large pull requests hide risk in plain sight

  • Reviewers skim past line 400
  • Conflicts pile up while the branch lives
  • One revert undoes a week of work
  • Nobody can tell what is safe to ship
Each bullet appears on its own press (class="step").

What we changed

Every plan is cut into PR-sized slices

A slice ships one behavior, end to end, behind a flag if needed.

  • Under 400 changed lines
  • Reviewable in one sitting
  • Revertible on its own

Review

Reviews start within the hour

Small diffs get picked up between meetings, not saved for Friday.

Tooling

A size check in a dozen lines

// fail the check when a PR outgrows a slice
const size = pr.additions + pr.deletions;
const limit = 1000;

if (size > limit) {
  fail(`${size} lines: split it`);
}
  • Runs on every push
  • Warns first, blocks later
  • Generated files excluded
Keep listings under ~14 lines. Spans: .c comment, .k keyword, .s string, .n number; mark = highlighted line.
