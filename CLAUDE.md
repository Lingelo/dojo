# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A **plugin marketplace** for Claude Code — not a traditional application. There is no build system, no package.json, no test runner. Plugins are metadata-driven (JSON + Markdown) and dynamically loaded by Claude Code.

## Architecture

```
.claude-plugin/marketplace.json   ← Plugin registry (name: "dojo")
plugins/<name>/
  ├── .claude-plugin/plugin.json  ← Metadata (name, version, description, author)
  ├── README.md
  ├── skills/<name>/SKILL.md      ← User-invocable skills (/command)
  ├── commands/<name>.md           ← Slash commands
  ├── agents/<name>.md             ← Agent system prompts
  ├── hooks/hooks.json             ← PreToolUse/Stop/Notification hooks
  ├── scripts/                     ← Node.js/Bash implementations
  ├── .mcp.json                    ← MCP server definitions
  └── .templates/                  ← Structured output templates
```

## Plugin Types

| Type | Format | Triggered by |
|------|--------|-------------|
| **Skill** | `SKILL.md` with YAML frontmatter | `/command` (e.g. `/kaizen:learn`, `/motion-video`) |
| **Command** | Markdown with YAML frontmatter | `/command` (e.g. `/my-command`) |
| **Agent** | Markdown system prompt | Automatic matching or explicit invocation |
| **Hook** | `hooks.json` → scripts | Tool events (PreToolUse, Stop, Notification, UserPromptSubmit) |
| **MCP** | `.mcp.json` | External service integration |

## 4 Plugins

- **motion-studio** — `/motion-video` skill: motion design as code. `scripts/render.mjs` renders HTML/CSS/SVG/Canvas compositions frame by frame (virtual clock + WAAPI/SMIL seeking, Playwright CDP capture → ffmpeg) to MP4/WebM/GIF/MOV, with sample-accurate synced sound (`data-sfx` / `__sfx()` cues, procedural SFX + music bed in `sfx.mjs`, beat/energy analysis in `audio.mjs` exposed as `window.__audio`), plus voice-over and subtitles (`voice.mjs` local TTS — Kokoro/Piper/say/SAPI/eSpeak or user recordings — measures real line timings, `captions.mjs` builds/parses SRT/VTT; `render.mjs --voice/--subs` mixes narration with music ducking, burns in captions and writes `.srt/.vtt`, exposed as `window.__captions`). Self-sufficient: `scripts/setup.mjs` reuses or auto-installs playwright-core, ffmpeg-static and Chrome Headless Shell into `${CLAUDE_PLUGIN_DATA}` (npm deps declared in its `package.json`).

- **slide-studio** — `/slides` skill: presentation decks as one HTML file from `skills/slides/assets/deck.html` (19 layouts as `data-layout`, 3 themes — `ink`, `paper`, `kaizen` (washi/sumi/vermilion, ensō + hanko drawn by the runtime) — + BRAND tokens, presenter runtime with steps/notes/overview); `scripts/slides.mjs` lists layouts, previews themes (`themes`), scaffolds (`new --layouts`), audits each slide in Chromium (`check`: overflow, collisions, safe area, contrast, density) and exports PDF/PNG/contact sheet. Self-sufficient: `scripts/setup.mjs`/`deps.mjs` reuse or auto-install playwright-core + Chrome Headless Shell into `${CLAUDE_PLUGIN_DATA}` (check/export only). Tests `node --test plugins/slide-studio/tests/*.test.mjs` (browser tests need `SLIDE_STUDIO_HOME` with a ready `env.json`); CI in `.github/workflows/slide-studio.yml`.

- **kaizen** (1.1.0) — the engine around agent-skills, which it **embeds** (one plugin; see agent-skills below). agent-skills does the work; Kaizen keeps only what it does not do. **4 skills** in agent-skills' anatomy (Overview, When to Use, Process, Common Rationalizations `| Excuse | Reality |`, Red Flags, Verification checklist — enforced by the contracts): `setup` (init, verify commands, `install settings`, doctor, next command; `check` read-only), `learn` (capture, `harvest`, `prune`), `metrics` (DORA approximated, learnings reuse, friction, cost per work item), `watch` (PR to "looks ready", never merges). agent-skills' skills load as `kaizen:<skill>` (`plugin.json` `skills: ["./skills", "./agent-skills/skills"]`). `commands/*.md` are generated from agent-skills' `.claude/commands/` with `agent-skills:` → `kaizen:` (`/kaizen:spec`, `plan`, `build`, `test`, `review`, `ship`, `constraints`, `code-simplify`, `webperf`), plus entry points onto its skills that have no command (`ENTRY_POINTS`: `/kaizen:ideate`, `debug`, `adr`, `security`, `doubt`, `migrate`); `agents/*.md` are its personas (`kaizen:code-reviewer`, `security-auditor`, `test-engineer`, `web-performance-auditor`) — all generated by `scripts/aliases.mjs` (`--check`), regenerated by `sync-agent-skills.yml`, never edited by hand. **8 hook registrations** (`hooks/hooks.json`): SessionStart heartbeat (`review-hooks.mjs --heartbeat` → `hooks-seen.json`); PreToolUse `secret-gate.mjs` (no `git commit` adding a secret, ~30 patterns in `secrets.mjs`, refuses `--no-verify`, active in every repo) and `review-gate.mjs` (no unreviewed `git push`: stopped once, Claude asks, the review first; a second push of the same commit reaches Claude Code's prompt, where only the user lets it out unreviewed (`push-offers.json`); refused in bypass mode; `review.require_before_push: false` turns it off; direct writes to protected state refused); PostToolUse `post-edit.mjs` on Write/Edit/MultiEdit/NotebookEdit (quality gate on for the session when a code file is edited; learnings matching `SPEC.md`/`tasks/` brought back once per content, a learning's `files:` globs once per session, as `additionalContext`) and `review-hooks.mjs --evidence` on Agent/Task/Skill (`code-reviewer` persona result recorded; `code-review-and-quality` skill marked in `review-pending.json`); Stop `quality-gate.mjs` (verify while the gate is on: green → off, red → exit 2 up to `gate.max_blocks`, then released), `review-hooks.mjs --stop` (reads the review the skill wrote from the transcript; verdict: non-empty Critical → blocked, `REQUEST CHANGES` → concerns, else ready; tree recorded in `reviews.json`), `ledger-hook.mjs` (each turn's new tokens charged to the work item in `ledger.jsonl`). `scripts/kaizen.mjs` is the zero-dependency CLI: status, root, init, config, detect, verify, doctor, install, gate, learnings, review, secrets, cost, metrics, pr — the README lists every command and hook script (contract). `agentskills.mjs` reads `SPEC.md`/`docs/SPEC.md`, `tasks/plan.md`, `tasks/todo.md`, `CONSTRAINTS.md` (read-only, tolerant); `doctor` checks `agent_skills` (embedded version; warns if `agent-skills@dojo` is enabled too) and `floor_guard`. Every gate stop is appended to `.kaizen/state/friction.jsonl`. Config (`lib.mjs` `DEFAULT_CONFIG`): `docs_root`, `language`, `verify`, `gate`, `review`, `secrets`, `pr` — each documented in `docs/reference/configuration.md` (contract). Tests: `node --test plugins/kaizen/tests/*.test.mjs` (unit, CLI, gates, PR with fake `gh`, contracts — run after any skill/command/CLI/doc change; `tests/diagrams.test.mjs` holds the SVGs to `docs/media/source/diagrams.mjs` (edit the generator, then run it — never the SVGs)). User docs: `plugins/kaizen/docs/` (getting-started, one guide per skill, concepts, reference, troubleshooting, positioning); end-to-end evals: `node plugins/kaizen/evals/run.mjs` (real `claude -p` with both plugins, costly); CI in `.github/workflows/kaizen.yml`.

- **kioku** — guarded knowledge vault, **a copy**: developed in its own repository ([Lingelo/kioku](https://github.com/Lingelo/kioku)), copied into `plugins/kioku/` by `.github/workflows/sync-kioku.yml` (hourly, by hand, or on a `kioku-updated` repository_dispatch) through `.github/scripts/sync-plugin.mjs --plugin kioku` (git archive of kioku's `main`, without `.github/`; refuses a source without `.claude-plugin/plugin.json` named `kioku` or with a symbolic link pointing outside the plugin; `plugins/kioku/.kioku-source` records the copied SHA). It is copied rather than listed as an external source because Claude Code's marketplace auto-update did not update it as one (observed 2026-11-03). **Never edit `plugins/kioku/`**: the next sync overwrites it; change kioku in its repository. No `version` field, so its version is this repository's commit SHA (any commit here, not only a sync, is an update); compatibility with a user's vault is a vault format number checked by the plugin. Tests `node --test .github/scripts/sync-plugin.test.mjs` (run by both sync workflows on pull requests that touch it).

- **agent-skills** (inside kaizen) — [Addy Osmani's agent-skills](https://github.com/addyosmani/agent-skills) (MIT, 0.6.15 at the first copy), **a copy embedded** in `plugins/kaizen/agent-skills/` — not a plugin of its own. Same script as kioku with `--into` (`.github/scripts/sync-plugin.mjs --plugin agent-skills --into plugins/kaizen/agent-skills`, marker `plugins/kaizen/agent-skills/.agent-skills-source`), but `.github/workflows/sync-agent-skills.yml` (daily, or by hand) **never pushes to main**: third-party code whose scripts run on users' machines, so each upstream change is a pull request from `sync/agent-skills` listing its executable changes first, with Kaizen's commands and agents regenerated. **Never edit `plugins/kaizen/agent-skills/`**: propose changes upstream. Its hooks (`hooks/*.sh`) are not registered: opt-in, per its own docs.

## Adding a New Plugin

1. Create `plugins/<name>/` with `.claude-plugin/plugin.json`
2. Add skills, commands, agents, hooks, or MCP config as needed
3. Register in `.claude-plugin/marketplace.json` (plugins array)
4. Add a `README.md`

## Key Conventions

- **Plugin JSON schema**: `plugin.json` must have `name`, `version`, `description`, `author`
- **SKILL.md frontmatter**: requires `name`, `description`, `allowed-tools` fields
- **Hook exit codes**: 0 = allow, 2 = block (message on stderr)
- **Hooks over deny rules**: gates use PreToolUse hooks, not settings.json deny rules (due to [known bugs](https://github.com/anthropics/claude-code/issues/6699))
- **Git commits**: conventional format `<type>(<JIRA>): <description>` — Jira extracted from branch name
- **Cross-platform**: scripts run on macOS, Linux and Windows (Kaizen CI covers all three)
- **No build step**: everything is interpreted at runtime by Claude Code
- **Learnings**: this repository's own lessons live in `docs/learnings/` (Kaizen format, `node plugins/kaizen/scripts/kaizen.mjs learnings validate`)
- **Language**: everything in the repo is written in English (READMEs, skills, agents, script and hook messages, docs). Skills and agents tell Claude to talk to the user in the user's language; Kaizen deliverables follow `language` in `.kaizen/config.json`. Exception: French-compat parsing/fixtures in Kaizen
